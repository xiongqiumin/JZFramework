# 手机端 UI 设计：`/agent` 对话页

> 2026-11-12 成文。**状态：仅设计，未落地**（现有代码只有 `@media (max-width: 820px)` 的抽屉式左栏）。
> 本文只谈"手机上长什么样、怎么点"，不涉及接口改动；视觉数值一律沿用 `web/ui/tokens.css`。

---

## 1. 定位与约束

手机端不是主战场，是**值班台**：

| 场景 | 需要什么 | 不需要什么 |
|---|---|---|
| 通勤路上看任务跑完没有 | 一眼看到状态、耗时、最后回复 | 看完整 44 次工具调用 |
| 临时补一句"顺便把 README 也改了" | 快速输入、图片附件 | 长文本编辑 |
| 客户现场看某个文件 | 打开文件、看几十行、复制路径 | 改代码 |

四条约束（与前端的硬约束一致，见 `web-ui-design.md` §1）：

1. 无构建：纯 CSS + 原生 JS，不加 npm 依赖；
2. 离线：不引 CDN、不引字体文件；
3. 单 exe：设计不能要求新的构建步骤；
4. **触控优先**：所有可点区域 ≥ 44×44，正文 ≥ 15px（iOS 上输入框小于 16px 会触发自动放大）。

## 2. 桌面元素盘点 → 手机处置

| 元素 | 桌面形态 | 手机处置 | 理由 |
|---|---|---|---|
| `.ag-rail`（竖条：文件/主机/任务/设置） | 最左 48px 常驻 | **改底部 tab bar** | 375px 宽里 48px 占 12.8%，且顶部按钮单手够不到 |
| `.ag-side`（文件树/主机/任务列表） | 左侧可拖宽栏 | **全宽抽屉**，从底部 tab 唤起 | 列表项是"一行文本 + 时间"，全宽才放得下完整指令 |
| `.cs-head`（标题 + 工作区 + 模型 + 状态 + 按钮） | 一行信息 + 一排按钮 | 压成**一行 + 更多菜单** | 工作区/模型在手机上不是每次都要看 |
| `.ag-tabs`（会话 / 文件） | 顶部 tab 栏 | **取消**，并入底部 tab | 手机上并排两套导航太挤 |
| `.cs-thread`（任务卡片流） | 多卡片纵向滚动 | 保留，但**工具块默认折叠** | 密度要降，先给结论再给过程 |
| `.cs-composer`（输入区） | 底部固定 | 保留，改造键盘适配 | 见 §5.3 |
| `.prev-bar`（路径 + 编码 + 复制） | 一行 | 保留，路径可点开 | 手机上复制路径是高频动作 |
| `.prev-body`（代码 + 行号） | 大字号等宽 | 字号降一档，**行号可关** | 小屏横向空间紧张 |
| `ctxMenu`（右键菜单） | 右键唤起 | **长按唤起** | 手机没有右键 |
| `connBar`（断线提示） | 顶部横幅 | 保留，加安全区 | 移动网络断线更常见 |
| 设置 / 目录选择器 | 居中 dialog | 改为**底部弹层**（sheet） | 拇指区，且键盘弹出时不遮输入 |

## 3. 信息架构

桌面是 `rail → 列表 → 内容` 三层，手机压成两层：

```
[底部 tab] 会话 · 任务 · 文件 · 主机
                ↓
        全屏内容区（会话 / 列表 / 文件）
```

没有第三层——**列表从底部 tab 打开后是全屏的**，选中一条就回到内容区。不保留"左边永远有一条列表"的常驻结构。

理由：手机上同时看到列表和内容，两边都只剩 180px，谁都不好用。

## 4. 线框

### 4.1 会话页（默认落地页）

```
┌──────────────────────────────────┐
│ ● cli-2 · 空闲            ⋯      │  ← 顶部：状态点 + agent 名 + 更多
├──────────────────────────────────┤
│                                  │
│  ┌────────────────────────────┐  │
│  │ 先跑一下单元测试，再看下覆盖率 │  │  ← 用户指令（右对齐没意义，全宽气泡）
│  │ cli-2 · 14:02              │  │
│  ├────────────────────────────┤  │
│  │ ▸ 思考（点击展开）           │  │  ← 过程块：默认折叠
│  │ ▸ 工具 × 12                 │  │
│  │                            │  │
│  │ 覆盖率 78%，缺口在 auth.ts  │  │  ← 最终回复：始终展开
│  │                            │  │
│  │ 已完成 · 1m12s              │  │  ← 状态 + 耗时（原来那行 meta）
│  └────────────────────────────┘  │
│                                  │
│  （上滑看更早的任务）              │
├──────────────────────────────────┤
│ [+] [🖼]  说点什么…        [发送] │  ← 底部输入，贴键盘
└──────────────────────────────────┘
```

要点：

- **状态点在标题左边**，颜色沿用 `--jz-ok / --jz-fail / --jz-accent`（执行中）——比 3 个字的徽章省空间；
- 用户指令不再做右对齐气泡（手机上左右分流会压缩到 70% 宽），改成**全宽浅底块**；
- 过程块折叠后只留一行摘要（`工具 × 12`），展开才看细节；
- 最终回复不折叠——这是手机上看任务唯一真正想读的东西；
- 任务卡片之间用 8px 空隙 + 1px 分隔线，不再用大间距（桌面 16px 在手机上太散）。

### 4.2 任务列表（底部 tab「任务」）

```
┌──────────────────────────────────┐
│ 任务                       ↻     │  ← 标题 + 刷新
├──────────────────────────────────┤
│ 今天                              │
│ ┌──────────────────────────────┐ │
│ │ ● 先跑一下单元测试，再看下覆盖率  │ │  ← 状态点 + 指令（两行截断）
│ │   14:02 · 已完成 · 1m12s      │ │
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │ ● 把 web_search 换成必应 RSS   │ │
│ │   13:40 · 已完成 · 38s        │ │
│ └──────────────────────────────┘ │
│ 昨天                              │
│ ┌──────────────────────────────┐ │
│ │ ● 修 cd 的路径问题             │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

- 每条 **≥ 64px 高**（两行文字 + 一行 meta），整行可点；
- 删除入口：**左滑露出删除**，不做常驻 ×（误触率高）；
- 分组沿用现有的今天 / 昨天 / 一周内 / 更早。

### 4.3 文件页

```
┌──────────────────────────────────┐
│ ▸ JZFramework / webui / app.js   │  ← 面包屑，末段高亮，点任意一段跳该目录
├──────────────────────────────────┤
│ 1  /* 页面特例: 只有…            │
│ 2  .wrap {                       │
│ 3    padding: 12px;              │
│ …                                │
├──────────────────────────────────┤
│ 12.3 KB · UTF-8            [复制] │  ← 底部条：大小 + 复制
└──────────────────────────────────┘
```

- 文件树是**一屏一层的列表**（Tap 进目录、左上角返回上一层），不做展开式树——手指点 ▸ 三角太小；
- 代码页去掉顶部标题栏（省 44px），改成面包屑 + 底部操作条；
- 行号在 ≤ 480 默认隐藏，长按/设置里可开；
- 横向滚动保留（代码不能折行）。

### 4.4 底部 tab bar

```
┌──────────────────────────────────┐
│                                  │
│           内容区                  │
│                                  │
├──────────────────────────────────┤
│   💬       📋       📂       🖥   │
│  会话     任务      文件      主机  │
│                                  │
│         ↑ 安全区内边距            │
└──────────────────────────────────┘
```

| 项 | 图标 | 落地 |
|---|---|---|
| 会话 | 💬 | 回到对话（当前 agent） |
| 任务 | 📋 | 任务列表 |
| 文件 | 📂 | 文件树（工作区根） |
| 主机 | 🖥 | agent / 目录列表 |

- 高 56px + `env(safe-area-inset-bottom)`；
- 当前项用 `--jz-accent` 上色 + 顶部 2px 指示条；
- **设置移到会话页的「⋯」菜单**——它一天点一次，不值得占一个 tab。

## 5. 关键交互

### 5.1 长按 = 右键

文件树项、任务卡片、代码块，长按 500ms 唤起同一个 `ctxMenu` 组件（位置取触点）。

```js
// 长按 + 抬起取消 + 滚动取消, 阈值 500ms / 位移 10px
```

`ctxMenu` 在手机上改为贴着触点上方显示，宽度 ≥ 200px（比桌面宽），每项高 44px。

### 5.2 返回键 / 手势

| 现状 | 手机行为 |
|---|---|
| 浏览器返回 | 有打开的 tab（文件）就先关 tab；没有就退出 |
| 抽屉打开 | 返回键先关抽屉（`history.pushState` 打一个占位） |

⚠ 不要接管"左边缘右滑"——那是 iOS 的返回手势，抢了会打架。

### 5.3 软键盘

用 `visualViewport` 把内容区高度顶上去，而不是让输入框被键盘盖住：

```js
const vv = window.visualViewport;
vv.addEventListener('resize', () => {
  document.documentElement.style.setProperty('--kb', (window.innerHeight - vv.height) + 'px');
});
```

- `.cs-thread` 底部 padding = `var(--kb) + 输入框高度`；
- `textarea` 字号 **16px**（小于 16 会触发 iOS 自动放大页面）；
- `enterkeyhint="send"`，但**不**把 Enter 当发送（手机上需要换行；发送用按钮）。

### 5.4 刷新

- 任务列表：下拉刷新（`touchstart → 下拉 60px → 松手`），只做这一处，不给内容区加手势；
- 会话页：不接下拉（会和"上滑看更早"冲突），靠 SSE 自动更新 + 顶部「⋯」里的刷新。

## 6. 视觉规格（手机）

| 项 | 值 | 说明 |
|---|---|---|
| 正文 | 15px / 行高 1.6 | 桌面 14 → 15，单手阅读距离更远 |
| 辅助信息 | 12px | 时间、耗时、模型名 |
| 输入框 | 16px | 防 iOS 缩放（硬性） |
| 代码 | 12px / 行高 1.5 | 比正文小一档，横向滚动 |
| 间距 | 8 / 12 / 16 | 只保留三档（桌面有六档） |
| 可点区域 | ≥ 44×44 | 图标按钮的 `padding` 撑到 44，不是把图标画大 |
| 圆角 | 卡片 10、按钮 6 | 沿用 tokens |
| 底部安全区 | `env(safe-area-inset-bottom)` | tab bar 与输入框都要 |

**断点**

| 断点 | 形态 |
|---|---|
| ≥ 900 | 桌面三栏（现状） |
| 640 ~ 899 | 平板：rail 保留，侧栏抽屉（现状 820 断点的延伸） |
| < 640 | 手机：底部 tab，全屏内容 |
| < 640 且横屏 | 两栏：列表 280px + 内容，恢复"边看列表边看内容" |

## 7. 状态设计

| 状态 | 呈现 |
|---|---|
| agent 离线 | 顶部一条浅红横幅"已离线，只能看历史"，输入框禁用并置灰 |
| 连接断开 | 沿用 `connBar`，但在手机上做成**顶部下滑横幅**（不占布局高度，3s 后收起为一个小圆点） |
| 任务执行中 | 状态点呼吸动画（`opacity` 1→0.35，1.4s 循环） |
| 空列表 | 一行居中提示 + 一个主按钮（"派一个任务"） |
| 加载中 | 骨架屏：任务卡片用 3 条灰色圆角条占位 |
| 内容过长 | 折叠到 12 行 + "展开全部"，避免一次渲染上万行卡死 |

## 9. 明确不做

1. **不做文件编辑**——手机键盘写代码是灾难，看和复制就够；
2. **不做虚拟滚动**——任务卡片最多几十个，虚拟滚动带来的是复杂度和 bug；
3. **不引入手势库**（Hammer.js 之类）——只用到长按和下拉两个手势，20 行原生代码就够；
4. **不接管浏览器返回手势**（左边缘右滑）；
5. **不做暗色模式**——与桌面保持一致（见 `web-ui-design.md` §4.4）；
6. **不把 44px 命中区做成"把界面撑大"**——图标尺寸不变，靠 padding 扩命中区。

## 10. 验收标准（做完怎么算对）

- [ ] 375×667（iPhone SE）上，会话页无需横向滚动，输入框不被键盘遮挡；
- [ ] 单手握持，底部 tab 四项都能用拇指点到（不含需要换手）；
- [ ] 任务列表每条 ≥ 64px，点击不误触；
- [ ] 代码页 80 列代码可横向滚动查看，行号与本行对齐；
- [ ] 长按文件树唤起菜单，位置不超出视口；
- [ ] 断网后 5s 内出现断线提示，恢复后自动消失；
- [ ] 连续切换 3 个底部 tab，不出现布局跳动。
